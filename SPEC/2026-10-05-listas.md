# Spec: Listas "Quero assistir" e "Já assisti"

- **Data:** 2026-10-05
- **Componente:** listas
- **Status:** aprovada para implementação
- **Substitui:** nenhuma. **Cancela** a spec planejada `filmes-ocultos` (ver "Impacto em outras specs").

## O quê

A pessoa pode guardar filmes em duas listas:

- **"Quero assistir"**: filmes que ela quer ver depois;
- **"Já assisti"**: filmes que ela já viu.

Os botões ficam na página do filme, ao lado das reações. Uma nova página **`/listas`** ("Minhas listas") mostra as duas listas em abas. Na aba "Já assisti", cada filme mostra a reação que a pessoa deu, se houver.

Filmes que estão em qualquer uma das listas deixam de aparecer nas recomendações.

## Por quê

Recomendar é só metade do trabalho: a pessoa precisa de um lugar para guardar o que achou interessante e lembrar o que já viu. O MovieMatch antigo não tinha nada disso.

As listas também melhoram as recomendações: um filme que a pessoa já assistiu ou já guardou não precisa ser sugerido de novo.

## Decisões técnicas

| Tema | Decisão |
|---|---|
| Status | Enum `public.status_lista`: `quero_assistir`, `assistido` |
| Uma lista por filme | Chave primária `(usuario_id, tmdb_id)`; marcar "Já assisti" tira o filme de "Quero assistir" e vice-versa |
| Desfazer | Clicar de novo no botão marcado tira o filme da lista |
| Dados copiados | `titulo`, `poster_path`, `ano` e `generos` do TMDB, buscados no servidor com `obterFilme`, para a página `/listas` não chamar a API por filme |
| Página | `/listas`, dentro da área logada; aba pela URL `?aba=quero` (padrão) ou `?aba=assistidos` |
| Motor | Os IDs das duas listas entram em `excluir` |
| Padrão de botão | O mesmo das reações: Server Action com `useActionState`, funciona sem JS, resultado esperado visível enquanto salva |

### Banco de dados

Migration `supabase/migrations/<timestamp>_listas.sql`:

- **Enum** `public.status_lista` (`quero_assistir`, `assistido`).
- **Tabela `public.lista_itens`**
  - `usuario_id uuid not null references auth.users(id) on delete cascade`
  - `tmdb_id int not null check (tmdb_id > 0)`
  - `status public.status_lista not null`
  - `titulo text not null check (char_length(titulo) between 1 and 300)`
  - `poster_path text` (pode ser nulo)
  - `ano smallint` (pode ser nulo)
  - `generos int[] not null default '{}'`
  - `adicionado_em` e `atualizado_em timestamptz not null default now()`, com o trigger `public.tocar_atualizado_em()` no update
  - `primary key (usuario_id, tmdb_id)`
- **RLS ligada**, para `authenticated`, sempre com `usuario_id = (select auth.uid())`: `select`, `insert`, `update` e `delete`.

### Código

```
src/features/listas/
  opcoes.ts      status, rótulos, ícones e abas
  schema.ts      zod: tmdbId inteiro positivo; status um dos 2 valores
  actions.ts     alternarLista(estado, formData)  ("use server")
  consultas.ts   obterItensLista(), obterStatusLista(tmdbId), idsNasListas()  (server-only)
  aba.ts         lerAba(valor): "quero" | "assistidos"
  components/
    botoes-lista.tsx    os 2 botões na página do filme
    abas-listas.tsx     as abas com contagem
    grade-filmes.tsx    a grade de cards da aba
```

**`alternarLista`**:

1. Valida `tmdbId` e `status`.
2. Lê o status atual do filme.
3. Se for o mesmo status: apaga o item (desfaz).
4. Senão: busca o filme com `obterFilme` (se não existir, devolve "Filme não encontrado.") e faz `upsert` com o novo status e os dados copiados. Ao trocar de status, `adicionado_em` passa a valer o momento da troca (o filme vai para o topo da nova aba).
5. Revalida `/filme/{id}`, `/listas` e `/dashboard`.

Erros voltam como `{ mensagem }` em pt-BR; o detalhe do banco vai só para o log.

### Botões na página do filme

Na área `acoes-filme`, depois das reações:

- Grupo com `aria-label="Minhas listas"` e dois botões de liga/desliga (`aria-pressed`):
  - **"Quero assistir"** (ícone `Bookmark`, preenchido quando marcado);
  - **"Já assisti"** (ícone `Check`).
- No máximo um marcado por vez.

### Página `/listas`

- Título (h1) "Minhas listas".
- Abas (links com `aria-current="page"` na aba ativa): **"Quero assistir (N)"** e **"Já assisti (N)"**.
- Grade responsiva de cards (o mesmo `CartaoFilme`), do item mais recente para o mais antigo, cada um levando a `/filme/{id}`.
- Na aba "Já assisti", abaixo de cada card, a reação dada ao filme, se houver: "❤️ Amei", "👍 Gostei" ou "👎 Não é pra mim" (ícones do lucide, com o texto).
- Aba vazia:
  - "Quero assistir": "Nada por aqui ainda. Marque “Quero assistir” na página de um filme para guardá-lo."
  - "Já assisti": "Nada por aqui ainda. Marque “Já assisti” nos filmes que você viu."
  - Em ambos, um link "Ver recomendações" para `/dashboard`.
- O header ganha o link **"Minhas listas"** quando há sessão.
- O proxy passa a proteger `/listas`.

### Dashboard

`/dashboard` passa os IDs das duas listas para `gerarRecomendacoes` em `excluir`.

## Impacto em outras specs

- **`filmes-ocultos` é cancelada.** A reação "Não é pra mim" (spec `reacoes`) já tira o filme das recomendações e reduz o peso dos gêneros dele, o que cobre o "não me interessa". As specs `dashboard`, `detalhes-filme` e `motor-recomendacao` passam a registrar isso no "Fora do escopo", no mesmo commit desta spec.
- **`reacoes`**: a página "Meus filmes com reações" fica coberta pela aba "Já assisti".

## Critérios de aceitação

1. `pnpm db:reset` aplica as migrations do zero sem erros.
2. **Testes unitários** (`pnpm test`) passam, cobrindo pelo menos:
   - o schema aceita os 2 status e rejeita outro valor e `tmdbId` inválido;
   - `lerAba`: `"assistidos"` → `"assistidos"`; ausente ou qualquer outro valor → `"quero"`;
   - os botões mostram "Quero assistir" e "Já assisti" e marcam só o status atual com `aria-pressed="true"`;
   - as abas mostram as contagens e marcam a aba ativa com `aria-current="page"`;
   - a grade mostra a reação do filme quando ela existe, e a mensagem de aba vazia quando não há itens.
3. **Testes de integração** (`pnpm test:integration`) passam, provando que:
   - o usuário adiciona, troca de status (`upsert`) e remove o próprio item;
   - o usuário A recebe zero linhas ao ler os itens de B e não consegue alterá-los nem apagá-los;
   - o usuário A não consegue inserir item com `usuario_id` de B;
   - o banco recusa status fora do enum e `tmdb_id` 0.
4. **Testes E2E** (`pnpm test:e2e`, TMDB falso) passam:
   - na página de um filme, "Quero assistir" fica marcado e o filme aparece em `/listas` na aba "Quero assistir (1)";
   - "Já assisti" no mesmo filme desmarca "Quero assistir", e o filme passa para a aba "Já assisti (1)", mostrando a reação "Amei" quando ela foi dada;
   - depois de entrar numa lista, o filme não aparece em nenhuma seção do dashboard;
   - clicar de novo em "Já assisti" tira o filme da lista, e a aba volta a mostrar a mensagem de vazio;
   - sem sessão, `/listas` leva a `/login?next=%2Flistas`;
   - os testes E2E anteriores continuam passando.
5. `pnpm lint`, `pnpm typecheck`, `pnpm build` e `pnpm check:secrets` terminam sem erros, e o CI passa na `main`.

## Fora do escopo

| Item | Onde fica |
|---|---|
| Listas personalizadas com nome | **não planejado** |
| Reordenar itens manualmente | **não planejado** |
| Compartilhar listas | **não planejado** |
| Botões de lista direto nos cards do dashboard | **depois**, se houver tempo |
| "Não me interessa" separado das reações | **cancelado**: coberto por "Não é pra mim" (spec `reacoes`) |
