# Spec: Perfil

- **Data:** 2026-10-05
- **Componente:** perfil
- **Status:** aprovada para implementação
- **Substitui:** nenhuma

## O quê

Uma página **`/perfil`** onde a pessoa:

1. **troca o nome** que aparece no app;
2. **edita as preferências** do onboarding (gêneros, duração e frequência) a qualquer momento.

O nome no header passa a ser um link para essa página.

## Por quê

O gosto muda: alguém que escolheu Ação e Drama no cadastro pode querer receber Terror amanhã. Hoje, as preferências só podem ser definidas uma vez, no onboarding, e o nome dado no cadastro não pode ser corrigido. O MovieMatch antigo também não permitia editar nada depois do cadastro.

Como o motor recalcula as recomendações a cada carregamento, mudar as preferências muda o dashboard na hora.

## Decisões técnicas

| Tema | Decisão |
|---|---|
| Rota | `src/app/(app)/perfil/page.tsx`, dentro da área logada (exige sessão e onboarding) |
| Nome | Server Action `atualizarNome` com o mesmo schema do cadastro (`nome` de 2 a 50 caracteres, sem espaços nas pontas); `update` em `perfis` (a RLS de update já existe) |
| Preferências | Server Action `atualizarPreferencias` com o `preferenciasSchema` do onboarding; `update` em `preferencias` |
| Retorno | As actions **não redirecionam**: devolvem `{ ok: true }` ou os erros; a página mostra "Alterações salvas." num `role="status"` |
| Revalidação | `revalidatePath("/", "layout")` depois de salvar, para o header, o dashboard e o perfil refletirem a mudança |
| Reuso | Os chips de gênero e os grupos de opções do onboarding viram componentes compartilhados em `src/features/preferencias/components/`; o wizard do onboarding continua igual por fora |
| Sem JS | Os dois formulários funcionam como formulários comuns |

### Página `/perfil`

- h1 "Seu perfil".
- **Seção "Seus dados"** (h2):
  - campo **Nome**, preenchido com o nome atual;
  - **Email** exibido só para leitura, com a nota "Não é possível alterar o email.";
  - botão **"Salvar nome"**.
- **Seção "Suas preferências"** (h2):
  - **Gêneros**: os 19 chips (`aria-pressed`), já marcados com os atuais; com 5 escolhidos, os demais ficam desabilitados e aparece "Você pode escolher até 5 gêneros.";
  - **Duração** e **Frequência**: os mesmos grupos de opções do onboarding, com a opção atual marcada;
  - botão **"Salvar preferências"** (desabilitado sem gênero escolhido).
- Cada seção mostra o próprio retorno: "Alterações salvas." ou a mensagem de erro (por campo no nome; geral nas preferências).
- O botão mostra "Salvando…" durante o envio.

### Header

O nome do usuário no header vira um link para `/perfil` (`aria-label="Seu perfil"` não é necessário: o texto do link é o nome).

### Proxy

O proxy passa a proteger `/perfil`.

## Critérios de aceitação

1. **Testes unitários** (`pnpm test`) passam, cobrindo pelo menos:
   - o formulário de nome vem preenchido com o nome atual e mostra o erro "Informe um nome entre 2 e 50 caracteres." para "A", sem chamar o servidor;
   - o formulário de preferências vem com os gêneros, a duração e a frequência atuais marcados;
   - com 5 gêneros marcados, os outros ficam desabilitados; sem nenhum, "Salvar preferências" fica desabilitado;
   - com retorno `{ ok: true }`, aparece "Alterações salvas." num `role="status"`.
2. **Testes de integração** (`pnpm test:integration`) passam, provando que o usuário atualiza o próprio nome e as próprias preferências, e que o banco recusa nome com 1 caractere e preferências com 6 gêneros (já cobertos em parte pelas specs anteriores; aqui o foco é o `update`).
3. **Testes E2E** (`pnpm test:e2e`, TMDB falso) passam:
   - clicar no nome no header leva a `/perfil`;
   - trocar o nome para "Novo Nome" e salvar mostra "Alterações salvas." e o header passa a mostrar "Novo Nome";
   - trocar os gêneros para só Terror e salvar faz o dashboard mostrar o resumo começando por "Terror" e a seção "Terror para você", e não mais "Ação para você";
   - sem sessão, `/perfil` leva a `/login?next=%2Fperfil`;
   - os testes E2E anteriores continuam passando.
4. `pnpm lint`, `pnpm typecheck`, `pnpm build` e `pnpm check:secrets` terminam sem erros, e o CI passa na `main`.

## Fora do escopo

| Item | Motivo / onde fica |
|---|---|
| Trocar email | **não planejado**: exigiria confirmação por email, desligada no projeto (spec `auth`) |
| Trocar ou recuperar senha | **não planejado** (fora do escopo da spec `auth`) |
| Foto de perfil | **não planejado** |
| Excluir a conta | **não planejado** |
| Estatísticas pessoais (gêneros mais vistos, reações) | spec `extras` |
